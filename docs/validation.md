# Validation scope

## v0.2.0 — checked 2026-11-02

- Skill-format validation passed; the main skill remains 121 lines, with specialized guidance loaded conditionally.
- 67 package-integrity checks passed; all 14 package-checker regression tests passed. The checker verifies local file targets and module metadata, not web availability, section anchors or design quality.
- Source inspection deepened from session summaries to targeted published slide/speaker-note passages for Shaver and Smith/Worch. The ledger records exact page ranges and remaining inspection limits. Added the Keltner/Haidt abstract as conceptual background and selected full-text sections of the Chirico et al. VR experiment; neither is presented as proof of a desktop-graybox recipe.
- Three fresh-context agent smoke tests exercised a constrained coastal-station review, a peaceful botanical-archive proposal and an evidence review of a museum test note. [Inputs and outputs](trials/v0.2-smoke-tests.md) are retained. All participant/session details in those inputs are synthetic fixtures, not human observations collected for this project.
- The first two runs made concrete, scoped proposals without changing protected routes, camera settings or required assistance. They separated inferred comprehension from emotional response. The garden response still began with targeted historical/relationship questions; the evaluation reference was tightened to require unprompted recall first.
- An independent document audit found an overstrict rule about text/prop-dependent inference. It was corrected to permit evidence from represented, tested temporary cues. The subsequent museum case retained that evidence and proposed changing the interview before rebuilding geometry.
- No engine adapter or Godot CSG behavior changed. The optional Godot module retains its documented 4.5 baseline and untested-runtime status.

These are instruction-following and package checks, not evidence that the skill consistently improves playable levels. No engine, controller traversal or human playtest was run for this update. There was no baseline condition, statistical comparison or formal held-out study.

## v0.1.0 — checked 2026-11-01

### Completed

- Skill-format validation using the authoring workflow's validator.
- 52 package-integrity checks, with no reported errors.
- 14 package-checker regression tests, all passing. They cover missing files, broken relative links, path escapes, symlinks, malformed module data and compatibility flags.
- Documentation review of the Godot CSG guidance against pinned 4.5 class references. The review strengthened checks for empty baked resources and explicitly separated moving-body collision from static CSG collision.
- Independent review of two plan-only graybox proposals. Both had useful decisions and unresolved construction details; one exposed conflicting width conventions, a ramp/landing overlap, and turning-space promises not represented in geometry. This led to an explicit spatial-accounting pass in the skill. It did not establish superiority of the skill condition.
- A fresh-context review using the skill detected a circular key/door dependency, stairs above the supplied step limit, a ramp above the supplied slope limit, hidden static CSG collision, misleading scenic route cues, and invalid screenshot-only evidence of grandeur. It preserved the distinction between nominal body fit and untested camera comfort. This is a bounded smoke test, not a human gameplay study.

### Not established

- No Godot scene or CSG recipe was executed as part of this release's package validation.
- No controller traversal, navigation bake, screenshot capture, performance benchmark or combat simulation is claimed.
- No human study of fun, awe, perceived scale or wayfinding was performed.
- No statistically supported improvement over a baseline agent is claimed.

The [evaluation procedure](../skills/impeccable-levels/references/evaluation.md) describes the next evidence to collect. Use the same project, controller, camera, tool access and total budget for baseline and skill conditions. Review ordinary player views and actual traversal, retain failures, and use neutral human observations. Package tests cannot substitute for those experiments.
